# Markdown（.md）使い方ガイド

txt ファイルから md ファイルへ移行するための入門資料です。

---

## 1. Markdown とは

- プレーンテキストに簡単な記号を付けて「見出し」「リスト」「表」などの構造を表現する書式です。
- 中身はただのテキストファイルなので、txt と同じようにメモ帳でも編集できます。
- GitHub、VS Code、Notion、Slack、Obsidian などで整形表示（プレビュー）されます。

### txt と比べたメリット

| 項目 | txt | md |
| --- | --- | --- |
| 見出し・構造 | 自分で記号を工夫 | `#` で統一的に表現 |
| 表示 | そのまま | 整形されて読みやすい |
| リンク・画像 | URL を貼るだけ | クリック可能・画像表示 |
| コード | 区別しにくい | ハイライト表示 |
| 目次生成・変換 | 不可 | HTML / PDF などへ変換可能 |

## 2. 取り扱い上の注意事項

### ファイル関連

1. **拡張子は `.md`**（`.markdown` も可だが `.md` が一般的）。
2. **文字コードは UTF-8 で保存**する。Shift_JIS だと GitHub などで文字化けします。
3. **改行コードは LF 推奨**（Windows の CRLF でも多くは動くが、Git 管理時は統一する）。
4. **ファイル名に空白や全角文字を避ける**と、リンクや URL で扱いやすい。
   - 良い例: `meeting-notes-2026-11.md`
   - 避けたい例: `会議 メモ.md`
5. `README.md` は GitHub でリポジトリのトップに自動表示される特別なファイルです。

### 書き方でつまずきやすい点

1. **改行が反映されない**
   - 1 回改行しただけでは、表示上は同じ段落としてつながることがあります。
   - 段落を分けたいときは **空行を 1 行入れる**。
   - 段落内で改行したいときは、行末に **半角スペース 2 つ** か `<br>` を入れる。
2. **記号の後ろには半角スペース**が必要
   - `#見出し` ✕ → `# 見出し` ○
   - `-項目` ✕ → `- 項目` ○
3. **全角スペースや全角記号は記法として認識されない**
   - `＃ 見出し` や `ー 項目` は無効です。
4. **ブロックの前後には空行を入れる**
   - 見出し・リスト・表・コードブロックの前後に空行を入れると、表示崩れを防げます。
5. **記号そのものを表示したいときはエスケープ**
   - `\*` のようにバックスラッシュを付ける → \*強調されない\*
6. **方言（フレーバー）がある**
   - 表・チェックボックスなどは「GitHub Flavored Markdown（GFM）」の拡張機能です。
   - 表示するツールによって対応状況が異なる場合があります。
7. **インデントはスペースで統一**（タブとスペースを混在させない）。入れ子リストは **4 スペース**にすると、GitHub でも本リポジトリの変換ツールでも同じように表示されます。

## 3. 基本の書き方

### 3.1 見出し

```markdown
# 見出し1（文書タイトル。1ファイルに1つが目安）
## 見出し2
### 見出し3
#### 見出し4
```

### 3.2 段落と改行

```markdown
1つ目の段落です。

2つ目の段落です（間に空行）。
行末にスペース2つで  
段落内改行になります。
```

### 3.3 強調

```markdown
**太字**
*斜体*
***太字＋斜体***
~~取り消し線~~
```

表示: **太字** / *斜体* / ***太字＋斜体*** / ~~取り消し線~~

> 日本語の文中で使う場合、前後に文字が密着していると認識されないことがあります。
> うまくいかないときは前後に半角スペースを入れてください。

### 3.4 箇条書き

```markdown
- 項目A
- 項目B
    - 子項目B-1（4スペースでインデント）
    - 子項目B-2
- 項目C
```

- 項目A
- 項目B
    - 子項目B-1
    - 子項目B-2
- 項目C

### 3.5 番号付きリスト

```markdown
1. 手順1
2. 手順2
3. 手順3
```

※ すべて `1.` と書いても自動で連番になります。

### 3.6 チェックリスト（GFM）

```markdown
- [ ] 未完了のタスク
- [x] 完了したタスク
```

- [ ] 未完了のタスク
- [x] 完了したタスク

### 3.7 リンク

```markdown
[GitHub](https://github.com)
<https://github.com>
[同じフォルダの別ファイル](./other.md)
[このファイル内の見出しへ](#3-基本の書き方)
```

### 3.8 画像

```markdown
![代替テキスト](./images/sample.png)
```

画像ファイルは `images/` などのフォルダにまとめ、**相対パス**で指定すると移動に強くなります。

### 3.9 引用

```markdown
> 引用文です。
> 複数行も書けます。
```

> 引用文です。
> 複数行も書けます。

### 3.10 コード

インライン: `` `npm install` `` → `npm install`

コードブロック（バッククォート3つ＋言語名でハイライト）:

````markdown
```python
print("Hello, Markdown!")
```
````

### 3.11 表（GFM）

```markdown
| 名前 | 役割 | 備考 |
| :--- | :---: | ---: |
| 田中 | リーダー | 左寄せ / 中央 / 右寄せ |
| 佐藤 | 開発 | |
```

| 名前 | 役割 | 備考 |
| :--- | :---: | ---: |
| 田中 | リーダー | 左寄せ / 中央 / 右寄せ |
| 佐藤 | 開発 | |

- `:---` 左寄せ、`:---:` 中央、`---:` 右寄せ
- セル内で `|` を使う場合は `\|` と書く

### 3.12 水平線

```markdown
---
```

※ テキストの直下に `---` を書くと「見出し」と解釈されることがあるので、前に空行を入れる。

### 3.13 折りたたみ（GitHub 等で対応）

```markdown
<details>
<summary>クリックで開く</summary>

ここに詳細を書きます。

</details>
```

### 3.14 注釈ボックス（GitHub のみ）

```markdown
> [!NOTE]
> 補足情報

> [!WARNING]
> 注意事項
```

## 4. 本リポジトリの変換ツールで使う場合の注意

`convert.py` / `build.py` / `app.py` は Python-Markdown（拡張: `fenced_code`, `tables`, `toc`, `sane_lists`）で変換しています。GitHub の表示とは一部異なります。

| 記法 | GitHub | 本ツール |
| --- | :---: | :---: |
| 見出し・強調・リスト・リンク・画像・引用 | ○ | ○ |
| コードブロック・表 | ○ | ○ |
| 入れ子リスト（2スペース） | ○ | ✕（同じ階層になる） |
| 入れ子リスト（4スペース） | ○ | ○ |
| 取り消し線 `~~文字~~` | ○ | ✕（記号のまま表示） |
| チェックリスト `- [ ]` | ○ | ✕（記号のまま表示） |
| 注釈ボックス `> [!NOTE]` | ○ | ✕（通常の引用になる） |
| Mermaid 図 | ○ | ○（`build.py` のみ） |
| `【要確認】` ハイライト | ✕ | ○（`build.py` のみ） |

- 手順書の構成ルールは [md-structure-rules.md](md-structure-rules.md) を参照してください。
- ファイル内の HTML はそのまま出力されます。信頼できるファイルだけを変換してください。

## 5. txt から md への書き換え例

**txt の場合**

```text
■会議メモ 2026/11/12
【参加者】
・田中
・佐藤
【決定事項】
1)リリース日を12/1に決定
2)テストは11/25まで
```

**md の場合**

```markdown
# 会議メモ 2026/11/12

## 参加者

- 田中
- 佐藤

## 決定事項

1. リリース日を 12/1 に決定
2. テストは 11/25 まで

## TODO

- [ ] テスト計画作成（佐藤）
```

置き換えの目安:

| txt でよく使う記号 | md の記法 |
| --- | --- |
| `■` `【】` | `#` / `##` 見出し |
| `・` | `- ` 箇条書き |
| `1)` `①` | `1. ` 番号付きリスト |
| `※` | `>` 引用 / `> [!NOTE]` |
| `----` 区切り | 見出し or `---` |

## 7. 運用のコツ

1. **1 ファイル 1 テーマ**、タイトルは `#` 1 つにする。
2. **見出しレベルを飛ばさない**（`#` の次は `##`、いきなり `####` にしない）。
3. **テンプレートを用意**しておく（議事録・日報・手順書など）。
4. **フォルダ構成を決める**（例: `docs/`, `notes/`, `images/`）。
5. 長い文書は冒頭に**目次**を置く（Markdown All in One で自動生成可）。
6. Git で管理すると変更履歴が差分で見やすい（md はテキストなので相性が良い）。

| コードブロック | ` ``` ` で囲む |
